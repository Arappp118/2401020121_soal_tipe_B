1. Pendahuluan dan Tujuan Praktikum

Ujian Tengah Semester (UTS) Praktikum Pemrograman Web bertujuan untuk mengukur capaian pembelajaran mahasiswa (CPMK091 dan CPMK092) dalam merancang dan mengembangkan aplikasi web dinamis berbasis Laravel dan basis data relasional MariaDB/MySQL. Pengerjaan dilakukan secara individual dengan berpedoman pada materi praktikum Modul 1 sampai Modul 7.

Pada Paket 2 Tipe B, studi kasus yang diselesaikan adalah Sistem Peminjaman Alat Laboratorium. Sistem ini mengelola pencatatan transaksi peminjaman alat inventaris laboratorium kampus. Aplikasi wajib mendukung operasi CRUD (Create, Read, Update, Delete) lengkap, pencarian data multi-kolom, filter data berdasarkan master alat, validasi data masukan secara ketat di sisi server (server-side validation), sanitasi data string, pencegahan duplikasi data unik, serta penanganan kesalahan database yang aman menggunakan koneksi PDO langsung (PHP Data Objects).

2. Analisis Kasus dan Kebutuhan Sistem

Laboratorium kampus memerlukan sistem digital untuk mendata peminjaman alat agar pencatatan barang tidak terjadi secara tumpang tindih. Pengguna sistem (petugas lab) membutuhkan fasilitas untuk:

  • Mencatat peminjaman alat baru dengan data lengkap (kode transaksi, nama peminjam, nomor identitas peminjam, jumlah alat yang dipinjam, dan pilihan alat).
  • Melihat daftar seluruh riwayat peminjaman beserta informasi detail nama alat dan indikator klasifikasi jumlah pinjaman (Banyak / Sedikit).
  • Memperbarui data transaksi peminjaman apabila terjadi kekeliruan pencatatan.
  • Menghapus rekaman transaksi yang telah dibatalkan atau selesai diproses.
  • Mencari data peminjaman berdasarkan kata kunci pada kode peminjaman, nama peminjam, atau nomor identitas peminjam.
  • Memfilter tampilan daftar hanya untuk jenis alat laboratorium tertentu.

3. Perancangan Basis Data dan Skema Relasi

Sistem dirancang secara tepat menggunakan dua tabel berelasi satu-ke-banyak (one-to-many) dengan mesin penyimpanan InnoDB:

3.1. Tabel Master: alat

Tabel master ini menampung daftar referensi alat yang tersedia di laboratorium.

Nama Kolom Tipe Data & Atribut Constraint Keterangan
id BIGINT UNSIGNED PRIMARY KEY, AUTO_INCREMENT Identifikator unik alat laboratorium.
nama_alat VARCHAR(100) NOT NULL, UNIQUE Nama alat (misal: Kamera, Proyektor). Tidak boleh ada duplikasi nama.

3.2. Tabel Transaksi: peminjaman_alat

Tabel transaksi ini menyimpan detail transaksi peminjaman yang dilakukan mahasiswa.

Nama Kolom Tipe Data & Atribut Constraint Keterangan
id BIGINT UNSIGNED PRIMARY KEY, AUTO_INCREMENT Identifikator unik transaksi peminjaman.
kode_peminjaman CHAR(10) NOT NULL, UNIQUE Kode unik transaksi 10 karakter alfanumerik (contoh: PM00000001).
nama_peminjam VARCHAR(100) NOT NULL Nama lengkap peminjam alat (panjang 3 - 100 karakter).
nomor_identitas VARCHAR(30) NOT NULL, UNIQUE Nomor identitas unik mahasiswa (panjang 5 - 30 karakter).
jumlah_alat TINYINT UNSIGNED NOT NULL, CHECK Jumlah unit alat yang dipinjam. Dibatasi CHECK (jumlah_alat BETWEEN 1 AND 10).
alat_id BIGINT UNSIGNED NOT NULL, FOREIGN KEY Merujuk ke alat(id) dengan ON UPDATE CASCADE ON DELETE RESTRICT.
created_at TIMESTAMP NULL Waktu rekaman transaksi dibuat.
updated_at TIMESTAMP NULL Waktu rekaman transaksi terakhir diperbarui.

3.3. Relasi dan Integritas Referensial

Relasi yang terbentuk adalah One-to-Many dari tabel alat ke peminjaman_alat (satu jenis alat dapat dipinjam dalam banyak transaksi peminjaman). Constraint integritas referensial yang diterapkan:

  • ON UPDATE CASCADE: Jika ID alat di tabel master mengalami perubahan, seluruh rekaman pada transaksi peminjaman yang merujuknya akan otomatis terbarui secara konsisten.
  • ON DELETE RESTRICT: Mencegah penghapusan rekaman alat pada tabel master jika alat tersebut masih tercatat digunakan pada tabel transaksi peminjaman. Hal ini menjaga integritas data laboratorium.
  • CHECK (jumlah_alat BETWEEN 1 AND 10): Menjamin di level basis data bahwa kuantitas peminjaman berada pada rentang logis 1 hingga 10 unit.

5. Penerapan Koneksi PDO dan Keamanan Basis Data

Sesuai instruksi ujian, akses basis data wajib menggunakan PDO melalui koneksi Laravel (DB::connection()->getPdo()) dan tidak diperbolehkan menggantikannya dengan Eloquent ORM pada operasi CRUD utama. 

// Mengambil instance PDO dari Laravel
$pdo = DB::connection()->getPdo();

// Query Prepared Statement dengan Named Parameter Binding
$stmt = $pdo->prepare(
    'SELECT p.*, a.nama_alat 
     FROM peminjaman_alat AS p
     JOIN alat AS a ON a.id = p.alat_id
     WHERE p.kode_peminjaman LIKE :kode 
        OR p.nama_peminjam LIKE :nama 
        OR p.nomor_identitas LIKE :identitas'
);
$stmt->execute([
    'kode' => '%' . $kataKunci . '%',
    'nama' => '%' . $kataKunci . '%',
    'identitas' => '%' . $kataKunci . '%',
]);
$data = $stmt->fetchAll(PDO::FETCH_ASSOC);

Keamanan yang Diimplementasikan:

  1. Pencegahan SQL Injection: Seluruh parameter masukan pengguna tidak pernah digabungkan secara langsung (string concatenation) ke dalam sintaks SQL, melainkan diikat menggunakan parameter binding pada prepare() dan execute().
  2. Penanganan Eksepsi try-catch & report(): Setiap operasi basis data dibungkus dalam blok try-catch. Jika terjadi galat (database exception), fungsi report($e) dipanggil untuk mencatat rincian teknis pada file log server (storage/logs/laravel.log), sementara pengguna di antarmuka web hanya menerima pesan sederhana dan aman (misal: "Terjadi kesalahan sistem saat memproses data.") tanpa mengekspos kredensial, username, kata sandi, maupun struktur query internal.
  3. Proteksi Token CSRF: Semua form POST, PUT, dan DELETE dilengkapi direktif @csrf untuk menangkal serangan Cross-Site Request Forgery.

6. Pengolahan Masukan, Sanitasi, dan Validasi Server-Side

Sebelum dilakukan pengujian validasi, semua input teks disanitasi menggunakan fungsi bawaan PHP trim() untuk menghilangkan spasi tidak perlu di awal dan akhir teks, serta strip_tags() untuk mensterilkan potensi tag HTML berbahaya (XSS).

Aturan validasi yang diterapkan pada Validator::make() meliputi:

  • kode_peminjaman: Wajib diisi, tepat 10 karakter, alfanumerik tanpa spasi (regex:/^[A-Za-z0-9]{10}$/), dan unik di tabel peminjaman_alat.
  • nama_peminjam: Wajib diisi, panjang antara 3 hingga 100 karakter.
  • nomor_identitas: Wajib diisi, panjang antara 5 hingga 30 karakter, dan unik di tabel peminjaman_alat.
  • jumlah_alat: Wajib diisi, berupa bilangan bulat (integer), dan bernilai antara 1 sampai 10.
  • alat_id: Wajib dipilih dan dipastikan eksistensinya di tabel master alat melalui query verifikasi PDO.
  • Persistensi Masukan: Jika validasi gagal, pengguna diarahkan kembali dengan withErrors() dan withInput() sehingga form otomatis mempertahankan input lama menggunakan pembantu old().

7. Helper Function PHP: statusJumlah()

Fungsi helper statusJumlah() dideklarasikan pada app/Helpers/helpers.php untuk mengklasifikasikan volume alat yang dipinjam: 

if (!function_exists('statusJumlah')) {
    function statusJumlah($jumlah_alat): string
    {
        $jumlah = (int) $jumlah_alat;
        if ($jumlah >= 3) {
            return 'Banyak';
        }
        return 'Sedikit';
    }
}

Fungsi ini dipanggil di dalam Blade pada setiap baris data tabel peminjaman: {{ statusJumlah($peminjaman['jumlah_alat']) }}. Pengecekan !function_exists() menjamin tidak terjadi tabrakan atau redeklarasi fungsi saat pemanggilan berulang.

10. Analisis Kendala, Perbaikan, dan GitHub Issue

Selama tahap pengembangan dan pengujian sistem, ditemukan sebuah kendala teknis pada validasi keunikan data saat operasi pembaruan (UPDATE):

Rincian Masalah (Issue Tracking)

  • Issue Title: Fix: Pengecekan Duplikat Kode Peminjaman dan Nomor Identitas Menolak Pembaruan Record Sendiri (Self-Collision)
  • Langkah Pemeriksaan: Pengguna mencoba memperbarui atribut nama_peminjam atau jumlah_alat pada record ID 1 tanpa mengubah kode_peminjaman. Sistem secara keliru menolak pembaruan dengan pesan "Kode peminjaman sudah digunakan.".
  • Penyebab Masalah: Query pengecekan duplikat pada update() controller tidak mengecualikan ID record yang sedang aktif diedit: 
    SELECT kode_peminjaman, nomor_identitas FROM peminjaman_alat WHERE kode_peminjaman = :kode OR nomor_identitas = :identitas
    Query di atas menemukan baris data record itu sendiri sehingga dianggap bentrok.
  • Perbaikan yang Dilakukan: Menambahkan klausul pengecualian AND id <> :id pada query prepared statement: 
    SELECT kode_peminjaman, nomor_identitas 
FROM peminjaman_alat 
WHERE (kode_peminjaman = :kode OR nomor_identitas = :identitas) 
  AND id <> :id LIMIT 1
  • Hasil Pengujian Ulang: Record ID 1 berhasil diperbarui dengan tetap mempertahankan kode dan identitasnya, sementara jika dicoba memasukkan kode milik record lain, sistem secara tepat menolak konflik data tersebut.

12. Kesimpulan

Aplikasi Sistem Peminjaman Alat Laboratorium (Paket 2 Tipe B) telah berhasil diselesaikan dengan memenuhi seluruh kriteria dan spesifikasi yang ditetapkan oleh tim dosen pengampu:

  1. Arsitektur basis data relasional MariaDB terdiri dari tepat 2 tabel (alat dan peminjaman_alat) yang dilengkapi kunci utama (PK), kunci tamu (FK) berelasi one-to-many, batasan CHECK (jumlah_alat BETWEEN 1 AND 10), UNIQUE, NOT NULL, ON UPDATE CASCADE, dan ON DELETE RESTRICT.
  2. Seluruh operasi CRUD, pencarian, dan filter dieksekusi 100% menggunakan PDO murni (Prepared Statements) dengan parameter binding tanpa ORM Eloquent pada transaksi inti.
  3. Validasi server-side, sanitasi string (trim dan strip_tags), token proteksi @csrf, dan penanganan input lama (old()) berfungsi sempurna.
  4. Fungsi helper PHP statusJumlah() berhasil menyajikan status klasifikasi jumlah dinamis pada Blade tanpa konflik redeklarasi.
  5. Seluruh tampilan dibangun secara taat instruksi menggunakan Blade dan HTML murni tanpa CSS maupun JavaScript eksternal.
  6. Seluruh 10 skenario pengujian telah lulus 100% melalui automated testing PHPUnit dan uji antarmuka nyata.
